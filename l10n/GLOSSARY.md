## Технические ограничения (жёсткие)
- Пакет подключается как language-pack плагин. i18next для плагинного языка использует
  упрощённое правило плюралов: count === 1 → `_one`, иначе `_other`. Формы `_few/_many` не работают.
  Поэтому `_other` должен быть грамматически верен для 0, 2, 5, 11, 21, 101…: «Найдено тем: {{value0}}».
- Плейсхолдеры `{{value0}}`, `{{count}}`, теги `<0>…</0>` — сохранять байт-в-байт, количество и порядок смысла.
- Не переводить: названия продуктов/брендов (Orca, Claude, Codex, GitHub, GitLab, Bitbucket, Jira, Linear,
  WSL, macOS, Windows, Linux, SSH, Tailscale…), CLI-команды, флаги, переменные окружения, пути, URL,
  имена файлов, фрагменты кода, клавиши (Cmd, Ctrl, Shift, Option, Alt, Enter, Esc), CSS-классы,
  значения конфигов (true/false, main, HEAD), форматы (JSON, YAML, Markdown).
- Ключевые слова поиска настроек индексируются вместе с английским оригиналом → переводить на русский.

## Стиль
- Кнопки и команды меню — инфинитив: «Открыть», «Сохранить», «Добавить репозиторий».
- Заголовки и подписи — с заглавной буквы только первое слово (sentence case), кроме имён собственных.
- Обращение — «вы» со строчной.
- Кавычки «ёлочки»; внутри кода/команд — исходные кавычки.
- Буква «ё» — пишем («удалённый», «включён»).
- Многоточие «…» сохраняем как в оригинале.
- Состояния: Enabled → «Включено», Disabled → «Отключено», Connected → «Подключено».
- Согласование рода с плейсхолдером, если род неизвестен: «{{value0}}: подключено».

**Правила**

1. **Множественное число в черновике описано верно для этой реализации.** Служебный язык `plugin<hex>` приводит к правилу `_one` только для `1`, `_other` для остальных чисел. Это подтверждается [i18next 26.3.1](https://raw.githubusercontent.com/i18next/i18next/v26.3.1/src/PluralResolver.js). Использовать нейтральное «Найдено тем: {{value0}}». Не считать это общим ограничением i18next или русского языка.
2. Проверять и строки без плюральных суффиксов: Orca местами выбирает единственное/множественное число непосредственно в компоненте. `{{value0}}` сам по себе не запускает склонение.
3. Сохранять имена, синтаксис и число вхождений плейсхолдеров; **порядок можно менять по русской грамматике**. Теги сохранять с корректной вложенностью и привязкой к соответствующему тексту.
4. Команды — инфинитив: «Открыть», «Сохранить». Названия разделов — существительные. Правило не распространять механически на «Да», «Нет», «Готово».
5. Состояния согласовывать: «Сервер подключён», «Устройство подключено», «Функция включена». Для неизвестного имени лучше «Подключение к {{value0}} установлено», чем универсальное «{{value0}}: подключено».
6. Сохранить строчное «вы», букву «ё», sentence case и кавычки «ёлочки». Внутренние кавычки — „лапки“.
7. В обычном тексте использовать `…`, сохраняя назначение многоточия. В командах, URL и примерах синтаксиса `...` не заменять.
8. Не переводить идентификаторы, команды, флаги, пути, имена файлов, API-поля и значения конфигурации. **Их человекочитаемые подписи переводить можно**: значение `true` сохраняется, подпись *Enabled* переводится.
9. Названия клавиш и реальные сочетания сохранять по платформе. Не заменять `Cmd` на `Ctrl` по собственной инициативе; обычные названия вроде *Space* переводить как «Пробел».
10. Переводить поисковые ключевые слова: код индексирует русский вариант вместе с английским. Исключение — бренды и записи `englishOnly`.
11. Уточнять, где выполняется действие: на этом устройстве, в WSL или на удалённом хосте. «Локально» относительно сервера не обязательно означает компьютер пользователя.
12. **Не весь раздел Plugins доступен language-pack.** Защищённые строки согласия, доверия и безопасности отклоняются валидатором; доступны только явно разрешённые исключения в `plugin-translatable-chrome.ts`. Это ограничение упаковки, а не основание обходить защиту.

**Ловушки**

- **Cursor** — продукт; *cursor* в настройках терминала — курсор. **Linear** — сервис; *linear* как характеристика — линейный.
- **Go** — язык, но **OpenCode Go** — название продукта/тарифа; *Go to terminal* — «Перейти к терминалу». **Pi** — агент, не число π.
- **Orca Relay**, **Claude Code**, **Codex**, **GitHub**, **GitLab**, **Ghostty**, **Warp** и названия шрифтов сохранять. Общие названия функций Orca переводить.
- **Detached HEAD** — «отсоединённый HEAD»: указатель не связан с веткой. В проверенном каталоге встречается в фильтрах боковой панели, **не в настройках**. Для отсоединённого сеанса нужен другой перевод.
- **Review**: ревью кода, проверка разрешений, просмотр результатов. *Review file* в диагностике — «файл для проверки», не «файл ревью».
- **Usage**: расход токенов/лимита, использование функций, занятое место, примеры использования. Один перевод на все ключи ошибочен.
- **Pinned**: закреплённая вкладка, но зафиксированная версия. **Stale**: устаревшие данные, но не обязательно недействительные учётные данные.
- **Disconnect ≠ stop ≠ remove ≠ revoke**: отключить соединение, остановить процесс, удалить запись, отозвать доступ. Потеря связи не доказывает завершение удалённой работы.
- **Account switching**: Claude переключает данные входа без переноса чатов; управляемая учётная запись Codex имеет собственный каталог с историей. *Remove account* здесь не означает удаление аккаунта у провайдера.
- **Workspace** у Linear/OpenCode — пространство соответствующего сервиса, а не рабочее пространство Orca.
- **Focus** и видимость проверять по компоненту: например, описание *Suppress While Focused* говорит о видимом рабочем дереве.
- Строки, разрезанные вокруг `<code>`, ссылок или плейсхолдеров, переводить как **целое предложение после сборки**. `fr.json` полезен для контекста, но не служит терминологическим эталоном.
## Дополнительные решения координатора
- Строки, которые во французском каталоге оставлены на английском, НЕ обязательно литералы: решай по смыслу. Литерал (команда, путь, ключ, id, CSS-класс, имя продукта, пример кода) → верни ровно английский текст. Обычное слово → переведи.
- Если строка — значение для поля ввода-примера (placeholder) вида «например, …» — переводи пояснение, пример-литерал оставляй.
- Sentence case: «Add Repository» → «Добавить репозиторий».
- Сохраняй начальные/конечные пробелы, двоеточия, точки и переводы строк (\n) как в оригинале.
- Строки-фрагменты предложения (начинаются/заканчиваются пробелом, предлогом, или соседствуют с {{value0}}/тегами) — открой компонент и посмотри, как они склеиваются; перевод должен читаться целиком.

## Краткий стиль (v1.2, ПРИОРИТЕТ над предыдущими правилами о формулировках)
Читатель — инженер: читает быстро, ценит плотность.
- Длина строки на русском — не больше английской (цель ≤ 1.0× по символам); для очень коротких подписей допустимо чуть больше, если иначе теряется смысл.
- Смысл и все технические детали сохраняются полностью: условия, ограничения, предупреждения о безопасности, где выполняется действие (это устройство / WSL / удалённый хост), команды и литералы.
- Убирать: «Любой, у кого есть…» → «По ссылке можно…»; «для того чтобы» → «чтобы»; «является», «осуществлять», «производить», «данный», «в том случае, если» → «если»; «с помощью» где можно без него; повторы подлежащего; пересказ заголовка в описании.
- Описания настроек — безличные или повелительные, без «Этот параметр определяет…» → «Определяет…», «Позволяет…» → глагол.
- unlisted link → «непубличная ссылка» (не «ссылка с доступом без публикации в каталоге»).
- Скобки-счётчики «(3)» и форма «Найдено тем: 3» остаются — это требование плюралов.
- Не сокращать словами с точкой («настр.», «польз.»), кроме устоявшихся «мин», «с», «шт.».
